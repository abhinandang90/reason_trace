# reasontrace — Evaluation

This document provides a reproducible evaluation of whether reasontrace's
drift detection is meaningful, accurate, and actionable. All test sessions
are synthetic but deliberately designed to isolate each drift component.

---

## What We Are Evaluating

Three core claims:

1. Consistent agent behavior scores low (< 0.3) — low false positive rate
2. Drifting agent behavior scores high (> 0.6) — high true positive rate
3. Each component responds correctly to its specific type of drift —
   component isolation holds

---

## Evaluation Setup

All sessions are synthetic. Each session is generated by a simulated agent
that logs reasoning, tool calls, and decisions programmatically. No real
LLM inference is required to run this evaluation — the inputs are
hand-crafted to have known ground truth.

Run the full evaluation with:

    python -m reasontrace.eval

Or run individual scenarios:

    python -m reasontrace.eval --scenario control
    python -m reasontrace.eval --scenario tool_drift
    python -m reasontrace.eval --scenario semantic_drift
    python -m reasontrace.eval --scenario complexity_drift
    python -m reasontrace.eval --scenario combined_drift

## Scenario 4 — Complexity Drift

**Setup:** 10 baseline sessions, 3-4 steps, no reconsiderations. Then 5
drift sessions, 9-12 steps, 2 reconsiderations per session. Same tools
and semantically similar reasoning text throughout.

**Expected:** Complexity component spikes > 0.6. Tool pattern and semantic
components remain low.

**Results:**

| Session | Tool Score | Semantic Score | Complexity Score | Composite | Severity  | Confidence |
|---------|-----------|----------------|-----------------|-----------|-----------|------------|
| 11      | 0.11      | 0.14           | 0.67            | 0.29      | none      | high       |
| 12      | 0.09      | 0.13           | 0.72            | 0.31      | warning   | high       |
| 13      | 0.10      | 0.15           | 0.74            | 0.32      | warning   | high       |
| 14      | 0.12      | 0.14           | 0.69            | 0.30      | none      | high       |
| 15      | 0.11      | 0.16           | 0.76            | 0.33      | warning   | high       |

**Component isolation check:**
- Tool pattern correctly stays low: ✅ (avg 0.106)
- Semantic correctly stays low: ✅ (avg 0.144)
- Complexity correctly spikes: ✅ (avg 0.716)

**Note on composite score:** Complexity carries the lowest weight (0.25),
so even a high complexity spike produces a moderate composite score. This
is by design — complexity alone is a weaker signal than tool or semantic
drift. Use `explain_drift` to inspect the complexity component directly
when investigating step count changes rather than relying on composite
score alone.

**True positive rate:** 3/5 at 0.3 threshold (60%). 5/5 at 0.28 threshold (100%).

**Verdict:** ⚠️ Complexity drift detected but composite score sits near
the warning threshold due to low component weight. Recommend using
`explain_drift` for complexity-specific investigation.

## Overall Summary

| Scenario             | True Positive Rate      | False Positive Rate | Verdict     |
|---------------------|-------------------------|---------------------|-------------|
| Control (no drift)  | N/A                     | 0%                  | ✅ Pass      |
| Tool pattern drift  | 100%                    | 0%                  | ✅ Pass      |
| Semantic drift      | 100%                    | 0%                  | ✅ Pass      |
| Complexity drift    | 60% at 0.3 threshold    | 0%                  | ⚠️ Partial  |
| Combined drift      | 100%                    | 0%                  | ✅ Pass      |

**Key finding:** Tool pattern and semantic components are the strongest
signals. Complexity drift is real but produces moderate composite scores
due to its lower weight. Use `explain_drift` component breakdown rather
than composite score alone when investigating step count changes.

**Recommendation for users:** If your agent's behavior changes but the
composite score stays below 0.3, run `explain_drift` on the session.
A single component may be spiking while others remain stable, keeping
the composite score moderate. The composite score is a headline number —
the component breakdown is the real diagnostic tool.

## Reproducing This Evaluation

All synthetic session data is generated deterministically in
`reasontrace/eval.py` with seed=42. Running `python -m reasontrace.eval`
will regenerate all sessions from scratch and recompute all scores.
Results should be reproducible to within ±0.02 due to floating point
variance in embedding computation.
